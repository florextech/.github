# Support

Florex Labs is a small, independent team. We read everything, but we cannot
promise a response time on free support.

---

## Before you ask

Most questions are already answered by one of these:

1. The repository's `README.md` and `docs/` directory
2. The repository's `CONTRIBUTING.md` — it covers setup, scripts, and the
   architecture constraints
3. Existing [issues and discussions](../../issues) — your question may already
   have an answer
4. The [Florex UI documentation](https://florexlabs.com) if you are using
   `@florexlabs/ui`

For an installed npm package, also check the [npm version history](https://www.npmjs.com/org/florexlabs)
— the problem may already be fixed upstream.

---

## Where to ask

| Topic | Best place |
| --- | --- |
| "How do I use this?" | [Discussions](../../discussions) or an issue |
| "Something is broken" | A [bug report](../../issues/new/choose) with repro steps |
| "I'd like this feature" | A [feature request](../../issues/new/choose) |
| "How do I contribute?" | [CONTRIBUTING.md](CONTRIBUTING.md) |
| **"Is this a vulnerability?"** | **[SECURITY.md](SECURITY.md) — not a public issue** |
| Commercial or product inquiry | **hello@florexlabs.com** |

Do not use public issues or discussions for security vulnerabilities. Follow
[SECURITY.md](SECURITY.md) so users are not exposed while we work on a fix.

---

## What makes a good question

Include:

- The repository and the exact version, tag, or commit SHA
- Your operating system, Node version, and package manager
- What you tried to do, what you expected, and what happened instead
- The full error output, in a code block, with secrets removed
- A minimal reproduction if you have one

A question with a minimal reproduction is usually answered on the first reply.
